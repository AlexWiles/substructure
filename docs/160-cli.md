`subs` is the command-line front end to the engine. It runs turns locally
against your worker and manages a hosted cloud app.

## Install

```sh
npm install -g @substructure.ai/cli
```

## Running a turn

`subs run` sends one input to the engine, streams the turn, and exits.

```sh
export ANTHROPIC_API_KEY=sk-ant-...
subs run \
    --worker-url http://localhost:4444 \
    --agent my-agent \
    --llm-provider anthropic \
    --output pretty \
    --input '{"type":"client.message","message":{"role":"user","content":"hi"}}'
```

Most of that belongs in a file instead — see [Environments](#environments).

| Flag | Meaning |
| --- | --- |
| `--input` | A `ClientInput` JSON. Required. Its `type` picks submit, resume, or settle. |
| `--agent` | The agent id the worker routes on. |
| `--worker-url` | Where the engine POSTs decisions. Default `http://localhost:3000/agent`. |
| `--session` | Resume a session. Omit to start one; the id is printed. |
| `--llm-provider` | Engine-run LLM provider: `anthropic`, `openai`, or `openrouter`. |
| `--output` | `ag-ui` (default), `jsonl`, or `pretty`. |
| `--db` | SQLite file. Default `substructure.db`. |

After a turn it prints the command to continue the session.

## Environments

One environment is one file is one engine. `substructure.toml` says which engine
the rest of it describes, and holds what you would otherwise pass on every
command. The CLI walks up from the working directory to find it, or takes
`-c <path>`.

`subs init local` writes a starter one here; `subs init remote subs.prod.toml`
writes the other kind under whatever name you give it.

`target = "local"` is an engine running in this process against a SQLite file —
what `subs run` and `subs serve` drive:

```toml title="substructure.toml"
target = "local"
db = "dev.substructure.db"   # events, sessions, and MCP credentials
log = "info"                 # RUST_LOG syntax; $RUST_LOG still wins

[worker]
url = "http://localhost:4444"
signing_secret_env = "WORKER_SIGNING_SECRET"

[llm]
provider = "anthropic"       # anthropic | openai | openrouter

[run]
agent = "my-agent"
output = "pretty"            # ag-ui | jsonl | pretty

[server]                     # `subs serve` only
host = "127.0.0.1"
port = 8080
dev = true

[slack]
agent = "my-agent"

[mcp.sentry]
url = "https://mcp.sentry.dev/mcp"
```

`target = "remote"` is a server speaking `/api/v1` — the hosted cloud, a
self-hosted deployment, or someone else's `subs serve`. Name it whatever you
like and select it with `-c`:

```toml title="subs.prod.toml"
target = "remote"
url = "https://api.substructure.ai"   # optional; this is the default
org = "org_01hx…"                     # written by `subs link`
app = "app_01hx…"

[worker]
url = "https://bot.example.com/agent" # `subs webhook set` pushes this

[mcp.sentry]
url = "https://mcp.sentry.dev/mcp"
```

The turn above becomes:

```sh
subs run --input '{"type":"client.message","message":{"role":"user","content":"hi"}}'
```

Precedence is **flag > environment variable > `substructure.toml` > default**,
so pinning a setting never takes an override away.

A command run against the wrong target says so rather than half-working:
`subs run` on a remote file, or `subs keys list` on a local one, is an error
naming the file and the target it needs.

`--input` and `--session` have no entry: they say what one run does, not how the
environment is set up. Neither do secrets — the file names the variable holding
the signing secret, the same way a connection names its `token_env`. A key that
belongs to the other target, or is simply misspelled, is a parse error rather
than a setting that silently does nothing.

`log` takes `RUST_LOG` syntax — a bare level, or per-target directives like
`substructure_core=debug,warn`. It applies from startup, so it covers what the
engine says while coming up. Without it, `subs run` shows errors only and
`subs serve` shows info.

See [Connectors](./85-connectors.md) for `[mcp.<id>]`.

## Local server

`subs serve` runs the engine as an HTTP server.

```sh
subs serve --dev --llm-provider anthropic --worker-url http://localhost:4444
```

`--dev` disables auth for local use. It also takes `--host`, `--port`, and
`--db`. `--slack-agent <id>` serves a [Slack bot](./105-slack.md) alongside.
Every one of these can live in `substructure.toml` instead.

## Cloud

Sign in and manage a hosted app.

| Command | Does |
| --- | --- |
| `subs login` / `logout` / `whoami` | Authenticate. |
| `subs apps` | List, create, show, rename, delete apps. |
| `subs keys` | Create and revoke API keys. |
| `subs sessions` | List sessions and stream their events. |
| `subs webhook` | Set the worker URL and signing secret. |
| `subs mcp` | Authorize the connections the file declares. |
| `subs link` | Pin an org and app in a `target = "remote"` file. |

`subs webhook set` with no URL pushes the `[worker].url` the file declares, so
the endpoint is stated once and applied rather than typed twice.
