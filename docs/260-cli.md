`subs` runs agents on your machine and administers a deployment.

```sh
npm install -g @substructure.ai/cli
```

Every command reads `substructure.toml` from the working directory. Pass `-c
<path>` to use another file. See [Config](./220-config.md).

## Where a command acts

**The `[remote]` section decides.** A file that names one describes a deployment
you administer, so that is what a command reads and writes. A file that names
none describes an engine you run here, so this machine's environment and this
machine's database are the whole answer.

```sh
subs agents list        # no [remote]: the agents this file declares
subs agents list        # with [remote]: the agents the deployment holds
```

`--url` targets a deployment for one command whatever the file says, and `--db`
targets a database the same way.

| | Command | With no `[remote]` |
| --- | --- | --- |
| **Either** | `sessions`, `agents list`/`show`, `llm list`, `mcp`, `doctor`, `slack` | reads the file and this machine |
| **Here** | `serve` | unchanged — this is the engine |
| **Either** | `run` | the turn runs on an engine here |
| **A deployment** | `keys`, `open`, `config log`, `projects show`, `agents secret`/`rotate-secret`, `llm set-key`/`delete-key` | says so, and how to get one |

A key or a signing secret here is an environment variable the file *names*,
never a value it holds — so the commands that bind one on a deployment tell you
which variable to export instead.

```console
$ subs llm set-key claude
Error: an engine here reads the key for [llm.claude] from $ANTHROPIC_API_KEY, so there is none to set.
  export ANTHROPIC_API_KEY=...
```

`login`, `logout`, and `whoami` are about a credential rather than a project,
and `apply` and `link` are how a file gets a `[remote]` in the first place. All
five work before there is one.

## Commands

| Command | Does |
| --- | --- |
| `subs run` | Run one turn and exit. |
| `subs serve` | Run the engine as an HTTP server. |
| `subs login` / `logout` / `whoami` | Authenticate against a deployment. |
| `subs apply` | Push the file to the deployment. |
| `subs doctor` | Show what the project still needs. |
| `subs projects` | List, show, and delete projects. |
| `subs agents` | List agents and read their signing secrets. |
| `subs llm` | List LLM blocks. Set and delete their keys. |
| `subs keys` | Create and revoke API keys. |
| `subs sessions` | List sessions and stream their events. |
| `subs mcp` | Authorize the connections the file declares. |
| `subs slack connect` | Install the Slack app into a workspace. |
| `subs link` | Pin an org and project in the file. |
| `subs config log` | Show what changed the configuration, and who changed it. |
| `subs open` | Open the project's dashboard. |

## `subs run`

Sends one input, streams the turn, and exits.

```sh
subs run --agent assistant -o pretty "hi"
```

| Flag | Meaning |
| --- | --- |
| `<message>` | The message to send, as a user turn. |
| `--agent` | Which `[agent.<id>]` to run. Falls back to `[run].agent`. |
| `--input` | A [`ClientInput`](./230-protocol.md#client-inputs) in JSON. Its `type` selects submit, resume, or settle. |
| `--session` | Continue a session. Omit it to start one. |
| `-o`, `--output` | `ag-ui` (default), `jsonl`, or `pretty`. |
| `--url` | Run the turn on the deployment at this URL. |
| `--db` | The SQLite file. |
| `-c` | The project file. |

The CLI checks the agent against the file before it creates a session. After a
turn, it prints the command to continue the session.

With a `[remote]`, the turn runs on the deployment. Nothing starts here — no
engine, no database, and no key, because the deployment holds them. The reply
still streams as it is written.

```console
$ subs run "hi"          # no [remote]: an engine here, writing substructure.db
$ subs run "hi"          # with [remote]: the deployment runs it
```

It uses the credential `subs login` stored, so there is no API key to create and
no token to mint. A turn started this way is an operator's, not an end user's:
it belongs to no one in particular, exactly as a turn run here does.

`-o jsonl` streams the engine's own events; `-o pretty` and `-o ag-ui` stream the
deployment's translation of them.

`--url` sends one turn to the server it names, whatever the file says. Point it
at a `subs serve` to use the engine already running there, rather than starting
a second one on the same database.

```sh
subs serve --no-auth                                   # one terminal
subs run --url http://127.0.0.1:8080 "hi"              # another
```

## `subs serve`

Runs the engine as an HTTP server.

```sh
subs serve --no-auth
```

| Flag | Meaning |
| --- | --- |
| `--host` | The address to bind. |
| `--port` | The port. |
| `--db` | The SQLite file. |
| `--no-auth` | Serve without client or worker authentication. |
| `--slack-agent <id>` | Also serve a Slack bot for DMs and unnamed channels. |
| `-c` | The project file. |

At startup it logs each declared agent and whether the engine or a worker
decides for it. See [Self-hosting](./180-self-hosting.md).

## `subs login`

```sh
subs login
subs login -c subs.prod.toml     # against the URL that file names
```

Authenticates with the OAuth device flow and stores a token under
`~/.config/substructure`.

Every cloud command takes `--url`. Without it, the command uses the file's
`[remote].url`, then `$SUBS_API_URL`, then the hosted cloud. The CLI stores
credentials per server, so you can be logged in to several deployments.

## `subs apply`

Pushes the file to the deployment. This is the only way to put configuration
into one.

```console
$ subs apply -c subs.prod.toml
Created project support-bot (proj_01hy…) in org_01hx…
Pinned proj_01hy… in subs.prod.toml
Applied 4 changes:
  llm.updated             claude (anthropic)
  agent.updated           support -> https://bot.example.com/agent
  mcp.connection_declared sentry (pending authorization)
  mcp.grant_added         sentry
Signing secrets minted:
  support: `subs agents secret support`

Action required:

  Authorize the [mcp.sentry] connection
    subs mcp login sentry -c subs.prod.toml
```

Apply creates the project when the file pins none. It is idempotent. An
unchanged file prints `No changes.` and exits 0.

Apply replaces. An agent, an LLM block, or a Slack channel that is not in the
file is one you removed.

```console
$ subs apply -c subs.prod.toml
Applied 1 changes:
  agent.removed           triage
```

Apply never sends a secret. It strips `api_key_env` and `signing_secret_env`. A
deployment refuses a document that carries one. See [Cloud](./170-cloud.md).

## `subs doctor`

Lists every step nobody has finished.

```console
$ subs doctor -c subs.prod.toml

Action required:

  Connect a Slack workspace
    subs slack connect -c subs.prod.toml

  Set the key for [llm.claude]
    subs llm set-key claude -c subs.prod.toml
```

With a `[remote]`, doctor asks the deployment. Without one, it reads this
machine: the variables that are empty, and the connections with no credential.

```console
$ subs doctor

Action required:

  Set $ANTHROPIC_API_KEY, the key for [llm.claude] (https://console.anthropic.com/settings/keys)
    export ANTHROPIC_API_KEY=...

  Authorize the [mcp.linear] connection
    subs mcp login linear
```

`--json` prints the list as JSON. With nothing left, doctor prints `Nothing to
do.`

## `subs agents`

```console
$ subs agents list
ID       LLM     MODEL                HOSTING                          SECRET
support  -       -                    https://bot.example.com/agent    set
triage   claude  claude-sonnet-4-5    engine                           -

$ subs agents show support          # never the signing secret
$ subs agents secret support        # the secret, on stdout
$ subs agents rotate-secret support # the old secret stops working at once
```

An agent exists because the file declares it. There is nothing to create.

Only `secret` and `rotate-secret` print a signing secret, so nothing else you
run can leave one in a terminal or a log.

With no `[remote]`, `list` and `show` read the file, and `SECRET` names the
variable a worker-hosted agent signs with.

```console
$ subs agents list
ID       LLM     MODEL                HOSTING                        SECRET
support  -       -                    https://bot.example.com/agent  $SUPPORT_SECRET
triage   claude  claude-sonnet-4-5    engine                         -
```

An engine here holds no secret to print or rotate, so those two say where the
secret is instead.

## `subs llm`

```console
$ subs llm list
NAME    TYPE       KEY
claude  anthropic  set

$ subs llm set-key claude              # from stdin
$ subs llm set-key claude --env MY_KEY # from an environment variable
$ subs llm delete-key claude
```

A key never appears in the command line. No read returns one.

With no `[remote]`, `list` reads the file and reports the variable each block
takes its key from.

```console
$ subs llm list
NAME    TYPE       KEY
claude  anthropic  $ANTHROPIC_API_KEY
byo     worker     n/a (your worker runs it)
```

## `subs keys`

```sh
subs keys create --label backend    # prints the key once, to stdout
subs keys list
subs keys revoke <key-id>
```

Pipe `create` into your secret store. See [Authentication](./190-auth.md).

## `subs sessions`

```sh
subs sessions list
subs sessions events <session-id> --stream
```

| Flag | Meaning |
| --- | --- |
| `--session-id` / `--agent-id` | Filter the list. |
| `--limit` / `--cursor` | Page the list. |
| `--from` | Only events after this sequence number. |
| `-f`, `--stream` | Follow the session live. |
| `-o`, `--output` | `jsonl` (default), `pretty`, or `ag-ui`. |
| `--db` | Read this SQLite database. |

Sessions come from whichever store holds them, by the rule
[above](#where-a-command-acts): with no `[remote]`, the commands read
`substructure.db` directly — the same sessions `subs run` and `subs serve`
write.

```console
$ subs run "hi"
...
$ subs sessions list
SESSION_ID                            AGENT    FIRST_EVENT           LAST_EVENT
0198f2c1-...                          oncall   2026-08-10T14:02:11Z  2026-08-10T14:02:14Z
```

`--db <path>` reads that file whatever the config says, and `--url` asks that
server. Locally, `--stream` polls the file, so it follows a `subs serve` running
beside it.

`-o pretty` replays a session as text, the way `subs run` prints a live turn.
Each turn is its own run, so a session of many turns replays as many.

```console
$ subs sessions events <session-id> -o pretty
Hello!
Goodbye!
```

See [Events](./240-events.md).

## `subs mcp`

```sh
subs mcp login sentry
subs mcp set-token github
subs mcp list
```

`login` opens a browser for consent. See [Connectors](./40-connectors.md).

## `subs slack connect`

```console
$ subs slack connect
Open this URL to add the bot to your workspace:
  https://slack.com/oauth/v2/authorize?…
Opened your browser to install.
Connected Acme (T0123ABC) to org_01hx…
```

If the file names no `[remote]`, the command prints the Socket Mode steps
instead. See [Slack](./130-slack.md).
